# ADR-0002 · GitHub и общее имя Forge Deck

Статус: принято. Дополняет ADR-0001 для второй платформы.

Приложение поддерживает GitHub и GitLab. Имя проекта и основная команда — Forge Deck / `forge-deck`, прежняя команда `gitlab-deck` остаётся совместимым запуском. Библиотечное имя сохранено для совместимости.

`Provider` выбирает платформу. App формирует нативные REST endpoints; транспорт использует `gh api` для GitHub и `glab api` для GitLab. Общий runner сохраняет ограничение одного дочернего процесса, тайм-аут, отмену, ограничение вывода, stdin для JSON изменений и очистку управляющих последовательностей. GitHub использует версию REST API 2022-11-28.

Ответы GitHub нормализуются в существующую модель на границе API. Исходные поля сохраняются, пользовательские тексты не переводятся. Настройки и действия формируются отдельно: GitHub PATCH и GitLab PUT меняют одно поле после подтверждения. GitHub отменяет workflow run целиком, повтор джобы затрагивает зависимые джобы; неподдерживаемые действия не отправляются.

В профиле сохраняются платформа, отдельные серверы и избранное по паре платформа/сервер. Новый путь `forge-deck/config.json` читает прежний профиль только при отсутствии нового, сохраняет неизвестные поля и не изменяет исходный файл. Права каталога 0700, файла 0600, запись атомарная.

Цена решения: нужны соответствующие CLI и штатная авторизация. Семантика платформ различается: общая лента PR не включает inline review comments; GitHub Search ограничен 1000 результатами, Contents — 1000 элементами каталога. Избранное GitHub использует существующий недокументированный `repositories/{id}` с проверкой возвращённого ID; при удалении этого маршрута понадобится хранить owner/name вместе с ID и читать документированный `repos/{owner}/{repo}`.

Проверки изменений выполняются в demo и через подставные CLI. Реальные мутации при разработке не запускаются. Подключения GitHub Enterprise проверяются тем же контрактом, но отдельного живого Enterprise-стенда нет.
